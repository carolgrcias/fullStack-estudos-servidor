📘 Aula 11: Banco de Dados (Create e Read)
Parte 1: A ideia em 2 minutos

Imagine que você abriu uma loja e anota os clientes num caderno. Funciona bem até você ter 5 mil clientes e precisar achar “aquele João que comprou em março”
Um *banco de dados* resolve exatamente isso: *guardar* informações de forma organizada e *encontrar* rápido quando precisar. Antigamente as empresas usavam papel e pastas. Hoje é tudo digital.

Existem dois grandes “estilos” de banco:

	         |       Relacional (SQL)	                              |      Não relacional (NoSQL)
Como guarda  |  Em tabelas (linhas e colunas), tipo planilha do Excel | De outras formas. No MongoDB, em documentos JSON
Vocabulário	 |  linha = registro/tupla · coluna = campo/atributo	  | documento · campo
Exemplos	 |  MySQL, PostgreSQL, Oracle	                          | MongoDB, Redis

SGBD (Sistema Gerenciador de Banco de Dados) é o programa que cuida do banco para você. Você pede “salva isso” ou “me acha aquilo” e ele faz. O MongoDB é um SGBD: gratuito, open-source e fácil de usar.

Parte 2: Como o MongoDB organiza as coisas.
Pense num armário de fichas:

🗄️ Banco de dados  (ex: exemplo_bd)   → o armário
   └── 📂 Collection (ex: usuarios)   → uma gaveta
         └── 📄 Documento             → uma ficha dentro da gaveta

Cada documento é um JSON, ou seja, pares de "chave": valor. Este é o exemplo do slide, de uma collection Livros:

{
  "codigo": "12345",
  "nome": "O Senhor dos Anéis",
  "editora": "Harper Collins",
  "ISBN": 8595086354,
  "paginas": 1568,
  "autor": "Tolkien, J.R.R."
}
👀 Repare: texto vai entre aspas, número vai sem aspas.

Traduzindo do relacional para o Mongo:
- Tabela Produtos → collection produtos
- Uma linha (01, Teclado, 110,00) → um documento { "codigo": "01", "descricao": "Teclado", "valor": 110.00 }
- Coluna → campo
MongoDB Compass é o “explorador de arquivos” do banco: uma tela gráfica onde você vê, adiciona e apaga documentos, collections e bancos inteiros. É ali que você confere se o seu código funcionou

Parte 3: CRUD, as 4 operações de qualquer sistema
Letra	Significa	Em português	Método no Mongo	    Quando
C	    Create	    Criar	        insertOne	        ✅ Hoje
R	    Read	    Ler/consultar	find	            ✅ Hoje
U	    Update	    Atualizar	    updateOne	        Aula 12
D	    Delete	    Apagar	        deleteOne	        Aula 12

Todo app é CRUD por baixo. No Instagram, por exemplo: criar conta (C), ver o feed (R), editar perfil (U), apagar um post (D).

Passo 6: Colar o código em cada arquivo
Na aula o código veio em pedaços. Aqui está cada arquivo completo, é só copiar e colar.

server.js:

js
// ===== 1. Importar as bibliotecas =====
var express = require("express");
var mongodb = require("mongodb");

// ===== 2. Configurar o Express =====
var app = express();
app.use(express.static("public"));               // libera os .html da pasta public
app.use(express.urlencoded({ extended: true })); // permite ler req.body dos formulários
app.set("view engine", "ejs");                   // as páginas de resposta ficam em views

// ===== 3. Conectar ao MongoDB =====
const MongoClient = mongodb.MongoClient;
const uri = `COLE_AQUI_SUA_STRING_DE_CONEXAO`;   // veja o Passo 7
const client = new MongoClient(uri, { useNewUrlParser: true });

// ===== 4. Abrir o banco e a collection =====
var dbo = client.db("exemplo_bd");
var usuarios = dbo.collection("usuarios");

/*Pegadinha clássica: o Mongo é “preguiçoso”. O banco e a collection só aparecem no Compass depois que você salva o primeiro documento. Se não aparecer antes disso, não é erro!*/

// ===== 5. CREATE: cadastrar usuário =====
app.post("/cadastrar_usuario", function (req, resp) {
  var data = { db_nome: req.body.nome, db_login: req.body.login, db_senha: req.body.senha };

  usuarios.insertOne(data, function (err) {
    if (err) {
      console.log(err);
      resp.render("resposta_usuario.ejs", { resposta: "Erro ao cadastrar usuário!" });
    } else {
      resp.render("resposta_usuario.ejs", { resposta: "Usuário cadastrado com sucesso!" });
    }
  });
});

// ===== 6. READ: logar usuário =====
app.post("/logar_usuario", function (req, resp) {
  // 1. O FILTRO: "procure fichas com ESTE login E ESTA senha"
  var data = { db_login: req.body.login, db_senha: req.body.senha };

  usuarios.find(data).toArray(function (err, items) {
    console.log(items);
    if (err) {
      resp.render("resposta_usuario.ejs", { resposta: "Erro ao logar usuário!" });
    } else if (items.length == 0) {
      resp.render("resposta_usuario.ejs", { resposta: "Usuário/senha não encontrado!" });
    } else {
      resp.render("resposta_usuario.ejs", { resposta: "Usuário logado com sucesso!" });
    }
  });
});

/*O que realmente importa aqui:
- req.body.nome é o valor digitado no input com name="nome". O nome tem que bater exatamente, e maiúscula faz diferença.
- db_nome: é o nome do campo no banco. O prefixo db_ é só uma convenção do professor para você não confundir “o que vem do formulário” com “o que está no banco”.
- insertOne(data, callback) significa “insira UM documento”. O callback roda quando o banco termina. Se err vier preenchido, deu problema*/

// ===== 7. Ligar o servidor (sempre no final) =====
app.listen(80, function () {
  console.log("Servidor rodando em http://localhost");
});

🧠 Pense assim: o MongoClient é o telefone que liga seu servidor ao banco, e a uri é o número para onde ele liga.
Dica: para o Mongo local, prefira 127.0.0.1 em vez de localhost. Nas versões novas do Node, localhost às vezes dá erro de conexão.

O que entender:
- find(filtro) significa “me traga todos os documentos que tenham esses valores”. Com vários campos no filtro, todos precisam bater (funciona como um E).
- .toArray(...): o find devolve uma espécie de “fila de resultados”, e o toArray transforma essa fila num array normal do JavaScript.
- items.length == 0 quer dizer lista vazia. Ninguém foi encontrado, então login ou senha estão errados.

Passo 7: Trocar a string de conexão
No server.js, substitua COLE_AQUI_SUA_STRING_DE_CONEXAO por uma destas opções:

- Se você usa o MongoDB online (Atlas), que é o que a aula usa: no site do Atlas, clique em Connect → Drivers e copie a string, que tem esta cara: mongodb+srv://seuusuario:<db_password>@cluster0.xxxxx.mongodb.net/ Troque <db_password> pela sua senha (sem os sinais < >).
- Se você instalou o MongoDB no seu computador: use mongodb://127.0.0.1:27017

🛠️ Passo a passo
Passo 1: Instalar o dotenv

O dotenv é a biblioteca que sabe abrir o cofre. No terminal, dentro de Servidor:

bash
npm install dotenv

Depois confira se "dotenv" apareceu no package.json, em "dependencies".

Passo 2: Criar o cofre (.env)
No VS Code, clique com o botão direito na pasta Servidor → New File.
Dê o nome .env: começa com ponto, sem nada antes e sem extensão (não é .env.txt!).
Dentro dele, escreva uma linha só, colando a sua string completa com a senha:
MONGO_URI=mongodb+srv://anacarolinagrcia_db_user:SUA_SENHA@cluster0.3zliwgb.mongodb.net/

⚠️ O formato do .env é bem rígido: NOME=valor

sem espaço antes ou depois do =
sem aspas, sem crases, sem ponto e vírgula

O MONGO_URI é o nome da gaveta do cofre. Você vai usar esse nome no próximo passo.

Passo 3: Fazer o servidor.js usar o cofre

A) Na primeiríssima linha do servidor.js (antes de todos os require), coloque:

js
require('dotenv').config();   // abre o cofre (.env)

B) Troque a linha da uri por:

js
const uri = process.env.MONGO_URI;   // pega a string de dentro do cofre

O começo do arquivo fica assim:

js
require('dotenv').config();

var http = require('http');
var express = require('express');
var colors = require('colors');
var bodyParser = require('body-parser');
var mongodb = require('mongodb');

var app = express();

// ===== Conectar ao MongoDB =====
const MongoClient = mongodb.MongoClient;
const uri = process.env.MONGO_URI;
const client = new MongoClient(uri, { useNewUrlParser: true });

Traduzindo:

require('dotenv').config() → “leia o arquivo .env e guarde o que tem lá dentro”
process.env → o lugar onde ficam essas configurações guardadas
process.env.MONGO_URI → “me dá o valor que está com o nome MONGO_URI”
Passo 4: Testar (antes de subir!)
Salve tudo, depois Ctrl + C e node servidor.js.
Acesse http://localhost/blog. Os posts precisam continuar aparecendo.

Pode aparecer no terminal uma linha parecida com [dotenv@...] injecting env (1) from .env. É normal e significa que deu certo: o (1) indica que ele leu 1 variável do cofre.

Se der erro na linha da uri (algo com undefined ou Invalid scheme), o cofre não foi aberto. Confira:

se o nome do arquivo é exatamente .env (e não .env.txt)
se ele está dentro de Servidor, ao lado do servidor.js
se o require('dotenv').config(); está na primeira linha
se você rodou o node servidor.js de dentro de Servidor

Passo 5: Configurar o porteiro (.gitignore)

Você já tem um .gitignore dentro de Servidor. Abra e deixe com estas duas linhas:

node_modules/
.env
node_modules/ → “não envie essa pasta”
.env → “não envie o cofre”

💡 Se o seu projeto já estiver ligado ao Git, o VS Code mostra os arquivos ignorados mais apagados (cinza) na barra lateral. É a confirmação visual de que o porteiro está funcionando
